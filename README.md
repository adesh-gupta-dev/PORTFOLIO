# Radiant Portfolio

Adesh Gupta's single-page portfolio, built with the existing Vite, React 18,
TypeScript, and Tailwind CSS setup. The interface follows the supplied Stitch
layout, updated with an electric blue/cyan palette, a generated technology-core
hero image, project screenshots, a CSS grid background, and controlled motion.
A persisted light theme remains available.

## Development

```sh
pnpm install --frozen-lockfile
pnpm dev
pnpm lint
pnpm typecheck
pnpm build
pnpm preview
```

`pnpm build` runs Vite and then `prerender.mjs`. The latter renders the same React
components into `dist/index.html`; the browser hydrates that content. Profile,
experience, projects, skills, and contact links are readable without JavaScript.
Use the package build command in deployment settings so prerendering runs.
The deployment output directory remains `dist`.

## Content and design

- `src/lib/portfolio.json`: shared editable content, including the confirmed
  Stitch experience, education, skills, and featured projects. Original projects
  remain in the archive and original credential links remain available.
- `src/components/*Section.tsx`: presentation of that content.
- `src/pages/Index.tsx`: section order and persisted theme.
- `src/components/Navbar.tsx`: desktop and mobile navigation, active sections,
  and Escape-to-close behavior.
- `src/components/ScrollReveal.tsx`: small, one-time intersection reveals;
  server-rendered content starts visible and keyboard focus reveals content.
- `src/index.css`: responsive styles, design tokens, visible focus, and
  reduced-motion overrides.

`ParticlesBackground.tsx` now renders lightweight decorative CSS layers. The
particle engine and typing-animation packages remain installed but are excluded
from the production bundle. Ambient scan motion stops for reduced-motion users.

Anime.js 4.5's lightweight WAAPI entry point powers the staggered hero accents,
one-time section reveals, and slow portrait-ring highlight through native browser
animations. The heading and portrait remain visible without a startup fade.
React effects revert animations on unmount or a reduced-motion change. Ring
motion pauses when the portrait is offscreen. Keyboard focus reveals pending content immediately;
server-rendered and no-JavaScript content starts visible. CSS still handles
simple hover/focus transitions, without a second animation on the same entrance
properties. Install dependencies with the existing pnpm setup (`pnpm install`).

Fonts are self-hosted Latin variable WOFF2 files in `public/fonts`, with the
original OFL licenses alongside them. Body and heading fonts are preloaded;
there is no render-blocking Google Fonts stylesheet. The bundled portrait and
two project screenshots have compressed responsive WebP variants selected by
`srcSet` and `sizes`. Their original files remain available, and custom image
URLs entered through the admin editor render without assuming variants exist.
Scroll reveal geometry comes from batched IntersectionObserver entries. An
unchanged public content response leaves the prerendered React tree and metadata
intact instead of triggering another full render during startup.

## Admin panel

Open `/admin` to edit the profile, email, resume and social links, projects,
experience, skill categories, education, certifications, contact text, section
headings, and SEO. Collections support adding, removal with confirmation,
reordering, and featured-project selection. Valid drafts are saved in the current
browser. Preview is private to the editor tab; JSON import and export provide
portable backups. Drafts do not change the public portfolio until published.

The panel checks the username and password on the server, creates an eight-hour
signed HTTP-only session cookie, and requires same-origin JSON requests and a
session-bound CSRF token for publishing. Production cookies use Secure,
SameSite=Strict and the `__Host-` prefix. Missing configuration disables sign-in;
there is no built-in default password. Password or session-key rotation
invalidates existing sessions. Never put credentials in a `VITE_` variable.

Configure these **server-only** environment variables in the existing Vercel
project, then redeploy. For local development, put them in an ignored `.env.local`
using `.env.example` as the template and restart `pnpm dev`:

| Variable               | Value                                                                                                 |
| ---------------------- | ----------------------------------------------------------------------------------------------------- |
| `ADMIN_USERNAME`       | Your chosen admin username                                                                            |
| `ADMIN_PASSWORD`       | At least 8 characters; a unique random password of 16+ characters is recommended                      |
| `ADMIN_SESSION_SECRET` | A random secret of at least 32 characters                                                             |
| `ADMIN_ORIGIN`         | `https://adeshgupta.site` (exact origin, no trailing slash)                                           |
| `GITHUB_CONTENT_TOKEN` | Fine-grained GitHub token restricted to the portfolio repository, with Contents read/write permission |
| `GITHUB_REPOSITORY`    | `adesh-gupta-dev/PORTFOLIO`                                                                           |
| `GITHUB_BRANCH`        | The branch Vercel deploys, currently `main`                                                           |

Generate a session secret locally with
`node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`.
Enter credentials directly in Vercel or your local environment; do not share
them in chat or commit them. The browser receives no GitHub token or server
environment values.

In `pnpm dev`, the authenticated admin uses the existing local
`src/lib/portfolio.json` directly. No GitHub token is required for local editing.
The button reads **Save to project**; saves validate the file revision, serialize
concurrent writes, and replace the file atomically. The public development page
loads those saved edits. Deploy the changed source to update the live site.
Loopback origins follow the actual local server port, including a fallback port
when 8080 is occupied. Local-file storage is disabled in production and Vercel
Functions. Restart `pnpm dev` after updating server code or environment values.

On Vercel, publishing updates only `src/lib/portfolio.json` through GitHub's Contents API.
The current file revision is checked to prevent one editor from overwriting
another editor's changes. Ensure this code and the JSON file exist on the target
branch before publishing. Protected branches may require a workflow change
before direct writes are permitted. Keep the existing Vercel Git integration
enabled so content commits rebuild the static HTML and metadata. The public
portfolio also reads the latest validated content via the server endpoint, with
a short CDN cache; if that endpoint is unavailable, bundled content remains
visible. Search-engine HTML and social metadata reflect the new content after
the rebuild finishes.

The `/admin` page and API are noindex; neither is included in the sitemap.
`vercel.json` adds only the admin rewrite and admin response headers. Existing
routes are not rewritten to the admin app. `pnpm dev` includes the same API via
a Vite development middleware; plain `pnpm preview` serves static files only.
If the API returns HTML or a content request fails, the editor displays the
specific problem and keeps the browser draft. Missing publishing credentials do
not invalidate a successful login.

Sign-in attempts are throttled per client and globally within each function
instance. Because serverless instances do not share memory, also configure a
Vercel Firewall rate limit for `POST /api/admin?action=login` before public use.
No database or authentication package is installed.

Run `pnpm test:admin` on Node 22.6+ to exercise authentication, secure cookies,
credential rotation, CSRF/origin checks, validation, conflict detection,
persistence, upstream-error privacy, and throttling against a mocked GitHub
service. The tests do not change a real repository.

## SEO and AEO checks

Run `pnpm build` followed by `pnpm test:seo` (Node 22.6+). The checks cover the
canonical, metadata escaping, linked JSON-LD, crawlable profile content, unique
IDs and headings, admin/404 noindex, robots rules, sitemap URLs, and freshness of
generated crawler files.

`public/llms.txt` follows the llms.txt proposal: a concise Markdown overview of
the actual public profile, project purposes and technologies, work experience,
skills, education, credentials, and contact links. `public/llm.txt` is an identical
compatibility alias for the singular spelling. Both are regenerated from the
editable content in every production build, so future admin content commits
update the summaries when Vercel rebuilds. They contain no credentials or admin
instructions. The homepage advertises `/llms.txt` through `rel="describedby"`.

Metadata includes one Person, WebSite, and ProfilePage plus CreativeWork entries
for visible projects. Project fragment identifiers resolve to their rendered
cards, and creators reference the same Person. No review, rating, award, or FAQ
markup is invented.

llms.txt is a proposed convenience for agents, not a replacement for robots,
sitemaps, useful HTML, or search indexing requirements. Google documents that
its AI search features do not require special AI files or special schema.
References: https://llmstxt.org/ and
https://developers.google.com/search/docs/appearance/ai-features.

A read-only production audit before these changes were deployed found the live
site still using the old Vercel-domain canonical and sitemap, and returning 404
for both llms file spellings. Deploy the current source with `pnpm build`, then
verify the actual production responses before treating these local checks as
deployment or indexing confirmation. Search Console submission is not performed
by this repository.

## Google Tag Manager configuration

Set `VITE_GTM_ID` to your `GTM-...` container ID in ignored `.env.local` for local
builds, and in the Vercel project's build environment for deployment. An empty
or missing value disables GTM; invalid IDs fail with a configuration error.
The ID is resolved at build time, so rebuild/redeploy after changing it.
The Vite HTML transform installs the configured container in the production
build. The small loader goes high in the head after the charset. It initializes
the data layer immediately, then fetches GTM asynchronously at low priority after
window load, two animation frames, and the next idle period (a two-second idle
timeout bounds the wait). Events queued before GTM loads are preserved.
Very short visits can end before the container loads. Audit the tags inside the
container separately to remove unused or duplicate tags; this code does not
change its published configuration. The noscript fallback is the first body
child. No analytics package is installed.
The container ID is public configuration, separate from all server credentials;
there is no hardcoded container ID in the application source.

The loader initializes only on the public homepage at `adeshgupta.site` or
`www.adeshgupta.site`. It skips admin pages, draft previews, framed pages,
localhost, and staging hostnames, and prevents duplicate initialization. The
admin production document has both snippets removed; the development server
does not inject either snippet. The production homepage retains Google's
standard noscript iframe for browsers with JavaScript disabled.

Build, then run `pnpm test:tracking` (Node 22.6+) to verify initialization,
exclusions, duplicate prevention, and separation of the public/admin documents.
These tests stub the external script instead of sending test traffic to Google.
After deployment, use Tag Assistant to verify the published container and its
configured tags; a successful local build does not verify live analytics events.

Installation reference:
https://support.google.com/tagmanager/answer/14847097.
